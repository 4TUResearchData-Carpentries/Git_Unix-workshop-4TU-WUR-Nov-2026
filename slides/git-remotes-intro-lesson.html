Git Remotes and collaboration

What are Git remotes?

Git remotes

  • Git was created to support collaboration among developers working on the Linux kernel.

  • Git is distributed: every developer has a local repository containing the full project history.

  • Git remotes allow these independent repositories to exchange changes, making collaboration possible without relying on a single central server.

  • Remote repositories (Git remotes) are versions of your project that are hosted on the Internet or somewhere on a network (private server, like a institutional server).

  • Collaborating with others involves managing these remote repositories and pushing and pulling data to and from them when you need to share work.

  • Examples: GitHub, GitLab, Bitbucket.

GitLab

  • GitLab started as a self-hosted tool, not a website (2011)
    GitLab began as an open-source side project by the Ukrainian developer Dmitriy Zaporozhets, who wanted a Git hosting tool his team could run on its own servers. It later grew into a company (GitLab Inc., founded in 2014) and the hosted service GitLab.com.

  • You can run your own GitLab: handy when data must stay in-house
    The core of GitLab is open source, and anyone can install it on their own server. Your code, and sometimes sensitive project files, stay on infrastructure your institution controls.

Gitlab vs GitHub

  • Same Git, different words: core vocabulary

    GitHub GitLab
    Pull request Merge request
    Repository Project (a repository plus its issues, CI, wiki, etc.)
    Organization Group (can contain subgroups)
    Issue Work items - Issue

    A fork, branch, and wiki mean the same on both platforms.

SSH connection

Secure Shell (SSH) is a cryptographic network protocol for operating network services securely over an unsecured network, by providing a secure channel between an SSH client and an SSH server.

SSH keys can be used to authenticate a user when interacting with a Git remote.
